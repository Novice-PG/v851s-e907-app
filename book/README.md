# 从一根串口到异构系统

> 副标题：基于 V851S、Zephyr 与 Linkr Bee 的从零实战
>
> 版本：第一版草稿（对应代码 `v851s-e907-app` v12，2026-11-14）
>
> 读者起点：会一点 C（变量、循环、函数、指针能看懂），
> 会用几条 Linux 命令（`ls`、`cd`、`cat`、`grep`、`ssh`），
> 没做过嵌入式，没写过驱动，没接触过蓝牙和 WebSocket。

---

## 这本书想解决什么问题

很多教程是“把代码贴一遍”，看完还是不会自己写。
这本书反过来：**先让你跑起来，再拆开，再让你改，最后让你从零做一套。**

学完以后，你应该能做到：

1. 说清楚一台设备从按下电源到网页可访问，中间经过了哪些层。
2. 看懂一个 AMP（异构多核）系统的内存地图、启动顺序和通信路径。
3. 在 Zephyr 上写线程、用信号量、用环形缓冲，移植一块新板子。
4. 在 Linux 上写一个能长期运行的串口 daemon，处理并发、背压和断线。
5. 用 WebSocket/HTTP/HTTPS 把设备能力暴露给浏览器，并知道安全边界。
6. 设计一个 BLE GATT 服务，理解 MTU、分片、notify/indicate。
7. 给同一套协议写 Web、TUI、CLI、Android 四种客户端。
8. 自己构建、打包、刷机、救砖、测试、写文档。
9. 拿到一份陌生代码，能按“三个问题”快速定位它在哪一层、失败会怎样。
10. 独立完成一个自己的异构设备小项目，而不是只会复现这本项目。

第 10 条是最终目标。前 9 条都是为它服务。

---

## 为什么用这个项目当主线

因为它“小得能讲完，又大得足够真实”：

- 有两个 CPU：A7 跑 Linux，E907 跑 Zephyr。
- 有真正的硬件：串口、引脚复用、时钟、NAND、Wi-Fi、BLE。
- 有完整的软件栈：bootloader、内核、rootfs、启动脚本、daemon、网页。
- 有真实的坑：4.9 内核缺 HCI 命令、BlueZ 的 EATT 解析 bug、
  XR829 单连接限制、慢客户端阻塞串口线程。
- 所有代码都能在仓库里找到，不是“伪代码”。

但书里的知识不只适用于这块板。换了 SoC、换了 RTOS、换了前端，
方法仍然成立：**先分层，再找边界，再看数据怎么过边界。**

## 读者画像与前置知识

### 你应该已经会

- C：变量、`if`/`for`、函数、数组、结构体、指针的基本读写。
- Linux：进目录、看文件、改权限、用 `ssh` 登录、用 `git` 拉代码。
- 英文：能看懂报错信息和 API 名字，不需要流利。

### 你不需要会

- 汇编、操作系统内核、设备树、蓝牙协议、Web 前端框架。
- 焊接、画 PCB、用示波器。书里会讲“怎么安全地接线”，但不要求硬件工程师水平。

### 你需要准备

- 一台 Linux 主机（Ubuntu/Debian 虚拟机也可以）。
- 一块 V851S 板子（或同类能跑 Linux + RTOS 的板子）。
- 一个 USB-TTL 串口模块（3.3 V）、杜邦线、目标板或回环测试。
- 一颗能接受“先跑通再理解”的耐心。

> 没有板子也能读前 10 章，但第 11 章以后必须动手。
> 嵌入式不是看会的，是烧坏过几块板子才会的（希望你不会）。

## 这本书怎么读

### 三遍法

| 遍数 | 目标 | 做法 |
|---|---|---|
| 第一遍：跑起来 | 知道每个东西“长什么样” | 照着做实验，不纠结每一行 |
| 第二遍：拆开 | 知道每层“为什么存在” | 读代码、画数据流、回答章末问题 |
| 第三遍：自己改 | 能改、能加、能替换 | 做“改造任务”，最后做一个完整项目 |

### 每章固定结构

1. **本章目标**：学完能做什么。
2. **先建立直觉**：生活比喻 + 一张图。
3. **最小实验**：能跑的命令/代码。
4. **拆开看**：关键代码、寄存器、协议。
5. **常见错误**：新手一定会踩的坑。
6. **练习与验收**：不做完不算学完。

### 建议节奏

| 周 | 内容 | 产出 |
|---|---|---|
| 1 | 第 0～4 章 | 环境准备好，能登录板子 |
| 2 | 第 5～10 章 | 能编译、能看启动日志 |
| 3～4 | 第 11～17 章 | 能改 E907 固件并烧录 |
| 5～7 | 第 18～25 章 | 能写 daemon、网页、BLE |
| 8～9 | 第 26～31 章 | 能写 TUI/CLI/Android 客户端 |
| 10～11 | 第 32～37 章 | 能打包、刷机、测试 |
| 12～14 | 第 38～40 章 | 独立完成一个综合项目 |

> 全职学 6～8 周，业余学 3～4 个月。不要赶，嵌入式的时间都花在调试上。

## 三个“不”

1. **不背 API。** 书里出现的函数，知道“为什么调用它”比记住参数重要。
2. **不跳过实验。** 看懂和跑通是两件事；跑通和改对是两件事。
3. **不害怕报错。** 嵌入式 80% 的时间在定位问题，书里会把错误信息当教材。

## 写作约定

- 命令前的 `$` 表示在主机执行，`#` 表示在板子执行。
- 路径 `<board-ip>` 是你板子的 IP，不要照抄示例。
- 标有 **危险** 的操作，先在虚拟机或备份上练。
- 代码块里的省略号 `...` 表示“这里省略了不重要的行”。
- 每章末尾的“验收”必须能独立完成，才算过关。
