# 第 5 章 数字电路与串口：从电压到字节

> 本章目标：

> 2. 会算波特率和吞吐，会判断“乱码”是不是参数错了。
> 3. 能安全接线，知道为什么两个 TX 不能对接。

> 5. 能自己完成一次串口回环实验。

## 5.1 先忘掉协议，只看电压

一根 UART 线在空闲时是**高电平**。以 3.3 V TTL 为例：

```text
空闲（idle）    3.3 V  ────────────────
起始位（start） 0 V    ┐
数据位                   └── 0/1 交替
停止位（stop）  3.3 V  ────────────────
```

接收方不需要时钟线，它靠**起始位的下降沿**对齐，然后按约定
的节奏在每个 bit 的中间采样：

```text
线：  ──┐  ┌──┐  ┌──────┐  ┌──
       idle│s │d0│d1 ... │p │stop
采样点：      ↑   ↑   ↑      ↑
            每个 bit 中间
```

这就是**异步串口**：没有共享时钟，只有双方事先约定的波特率。

> 因为靠“约定时间”采样，双方时钟误差不能太大。
> 通常要求总误差小于 2%～3%，否则采样点会漂到隔壁 bit。

### 电平标准不止一种

| 标准 | 逻辑 1 | 逻辑 0 | 能不能直连 SoC |
|---|---|---|---|
| 3.3 V TTL | 3.3 V | 0 V | 可以（绝大多数板子） |
| 5 V TTL | 5 V | 0 V | 不行，可能烧引脚 |
| RS-232 | −3～−15 V | +3～+15 V | 绝对不行，要转换芯片 |
| RS-485 | 差分 A/B | 差分 A/B | 要收发器 |

> 看到“DB9 串口”先问：是 RS-232 还是 TTL？示波器/万用表量一下，
> 或者看板子上有没有 MAX3232 之类的芯片。**电压不对会烧引脚。**

### 实验 5.1：量一下空闲电平

如果有万用表：

1. 黑表笔接 GND。
2. 红表笔接目标板 TX。
3. 空闲时应读到接近 3.3 V（或 5 V，取决于板子）。

如果读到 0 V，可能：没有共地、线接错、对方没上电、
或者那个脚根本不是 UART TX。

> 没有万用表也行：先共地，只接 RX 到电脑的 RX，用串口工具看。
> 但“先量电平”是最便宜的保护。

## 5.2 一帧到底长什么样

以最常见的 **115200 8N1** 为例：

| 字段 | 位数 | 说明 |
|---|---|---|
| 起始位 | 1 | 低电平，告诉对方“开始了” |
| 数据位 | 8 | 低位先发（LSB first） |
| 校验位 | 0 | N = None，无校验 |
| 停止位 | 1 | 高电平，告诉对方“这帧结束” |

总共 10 个 bit 传送 1 个字节。

### 发送 `0x41`（字符 `A`）

`0x41` 的二进制是 `0100 0001`。低位先发，所以线上顺序是：

```text
start  d0  d1  d2  d3  d4  d5  d6  d7  stop
  0     1   0   0   0   0   0   1   0    1
```

注意 d0 是最低位 1，d6 是最高位 0（8 位数据只有 7 位有效，
最高位是 0）。画成波形时，从左到右是时间。

### 为什么要有起始位

如果数据线一直是高，接收方无法知道“什么时候开始”。
起始位是一个强制的低脉冲，接收方检测到下降沿后，
等 1.5 个 bit 时间，正好落在 d0 的中间，然后每 1 个 bit 采一次。

### 校验位

- `E`（even）：数据和校验位中 1 的个数为偶数。
- `O`（odd）：1 的个数为奇数。
- `N`（none）：不校验。

校验只能发现**奇数个 bit 翻转**，不能纠错。长距离、干扰大时
才用；板内短距离通常 8N1。

### 停止位

可以是 1、1.5、2 位。停止位给接收方一点恢复时间，也用于
检测“帧错误”（停止位不是高，说明波特率不对或干扰）。

> 你不需要背波形。只要记住：**参数不一致 = 乱码。**
> 8N1 里的三个数字分别是数据位、校验、停止位。

## 5.3 波特率：算清楚就不会乱猜

### 定义

波特率是**每秒传送的 bit 数**（这里等于符号率）。115200 表示
每秒 115200 个 bit。

### 每秒多少字节

```text
每字节 10 bit（1 起始 + 8 数据 + 1 停止）
115200 / 10 = 11520 字节/秒 ≈ 11.25 KiB/s
```

所以：

| 波特率 | 字节/秒（8N1） | 传 1 KiB 需要 |
|---|---|---|
| 9600 | 960 | 约 1.07 s |
| 57600 | 5760 | 约 178 ms |
| 115200 | 11520 | 约 89 ms |
| 921600 | 92160 | 约 11 ms |
| 1500000 | 150000 | 约 6.8 ms |
| 4000000 | 400000 | 约 2.6 ms |

这解释了为什么：

- 网页粘贴 100 KB 到 115200 的串口要 ~9 秒。
- E907 的 64 KiB 环形缓冲在 115200 下能吸收 ~5.7 秒突发。
- BLE 再快，也快不过串口这条“细管子”。

### 常见波特率

```text
1200 2400 4800 9600 19200 38400 57600 115200
230400 460800 921600 1500000 2000000 3000000 4000000
```

不是任意值都能精准生成。UART 用分频器从时钟分频，实际波特率
和标称值有误差。**误差超过 2%～3% 就可能开始丢字节。**

### 实验 5.2：故意用错波特率

把串口工具设成 57600，而目标板是 115200：

- 你会看到乱码。
- 有时能偶尔认出一两个字符，因为采样点偶尔落对。

再把两端都设成 115200：

- 正常。

> “乱码”的第一嫌疑永远是波特率，第二是数据位/校验/停止位，
> 第三是地线，第四是电平标准。按这个顺序查。

## 5.4 接线：三根线，四个坑

### 最小连接

```text
设备 A                设备 B
  TX  ───────────────► RX
  RX  ◄─────────────── TX
  GND ──────────────── GND
```

- **TX 接 RX，RX 接 TX**（交叉）。
- **GND 必须共地**，否则双方没有共同的 0 V 参考。
- 只接 TX/RX 不接地，可能“看起来能用”，但一长就出错。

### 坑一：两个 TX 对接

```text
设备 A TX ────┬──── 设备 B TX     ← 错误
              │
        一个想拉高，一个想拉低
```

轻则乱码，重则其中一方输出级过流发热。**永远不要两个输出对接。**

这就是为什么这块板反复强调：

> **PE12（E907 的 UART3 TX）不能接 UART0 的 TX0（PH9）。**
> PH9 已经在输出 Linux 调试日志，两个 TX 对打会互相破坏，
> 甚至损坏引脚。

### 坑二：忘了共地

只接 TX/RX，双方电源独立时，电压参考漂移，接收方可能把
高电平判成低。表现是“有时正常，有时乱码”。

### 坑三：5 V 接 3.3 V

V851S 的 IO 是 3.3 V。5 V TTL 直接进来可能超过绝对最大额定值。
需要电平转换（电阻分压只适合单向、低速，正规用 TXS0108 之类）。

### 坑四：把 RS-232 当 TTL

电脑主板上的 9 针串口是 RS-232，±12 V。直接接 SoC 会烧。
用 USB-TTL 模块（CH340、CP2102、FT232）就对了。

### 这块板上的两个串口

| 设备节点 | 芯片 | 接到哪 | 用途 |
|---|---|---|---|
| `/dev/ttyACM0` | CH343P（Type-C 一面） | A7 UART0 | Linux 控制台 |
| `/dev/ttyUSB0` | CH340 | E907 UART3（PE12/PE13） | 目标串口 |

> 所以“串口打不开”经常不是软件问题，而是 Type-C 插反了：
> 一面是 USB 转串口，另一面是 SoC 的 USB OTG（FEL/主机）。

### 实验 5.3：确认你插的是哪个口

```sh
dmesg | tail -20
ls -l /dev/ttyACM* /dev/ttyUSB*
```

- 看到 `cdc_acm` → `/dev/ttyACM0`，是 A7 控制台。
- 看到 `ch341` → `/dev/ttyUSB0`，是 E907 目标串口。

然后：

```sh
picocom -b 115200 /dev/ttyACM0
```

按回车，应该看到登录提示或内核日志。退出：`Ctrl-A` 然后 `Ctrl-X`。

## 5.5 FIFO、中断、溢出：为什么 ISR 要短

### UART 内部有个小队列

ns16550 这类 UART 有一个 FIFO（先入先出缓冲），常见 16 或 64 字节：

```text
线上来的字节 → [ FIFO ] → CPU 读走
```

CPU 不需要每来一个 bit 就处理，而是等 FIFO 里攒到一定数量
（触发阈值）或超时，再产生中断。

### 溢出（overrun）

如果 FIFO 满了，CPU 还没读走，新来的字节就丢了，这叫 overrun。
表现：

- 数据少了一段。
- 日志里出现 `overrun` 错误。
- `@i?` 的 `uart dropped` 增加。

### 所以 ISR 只做搬运

固件里的中断服务程序：

```c
static void uart_isr(const struct device *dev, void *user_data)
{
    uint8_t buf[64];

    uart_irq_update(dev);
    while (uart_irq_is_pending(dev)) {
        int n;

        if (!uart_irq_rx_ready(dev)) {
            break;
        }
        n = uart_fifo_read(dev, buf, sizeof(buf));
        if (n <= 0) {
            break;
        }
        rx_push(buf, (uint32_t)n);
    }
    k_sem_give(&uart_rx_sem);
}
```

它只做三件事：

1. 把 FIFO 里的字节读进环形缓冲。
2. 记录总数/丢弃数（原子操作）。
3. 唤醒处理线程。

**不在 ISR 里解析协议、不打印日志、不睡眠、不发网络包。**
那些事交给线程。

### 为什么还有轮询兜底

```c
(void)k_sem_take(&uart_rx_sem, K_MSEC(RX_POLL_MS));
uart_poll_rx();
```

这块板的 CLIC 中断路由曾经不稳定。轮询让“中断没来”只变成
20 ms 的延迟，而不是整条桥失效。

> 这是典型的工程取舍：**先保证功能，再优化延迟。**
> 轮询会多花一点 CPU，但比“偶发丢一整天数据”好。

### 中断里读 FIFO 也要注意并发

注释写得很清楚：

```c
/* The ns16550 driver does not serialise uart_fifo_read() between a thread
 * and its own ISR, so mask interrupts while the polling thread reads the
 * FIFO. */
key = irq_lock();
do {
    n = uart_fifo_read(uart_dev, buf, sizeof(buf));
    ...
} while (n > 0);
irq_unlock(key);
```

线程和 ISR 都会读同一个 FIFO，必须互斥，否则可能读到半截状态。

## 5.6 流控：RTS/CTS 是什么

当接收方快满了，它可以拉高 RTS（Request To Send）告诉对方
“先别发”。发送方看到 CTS（Clear To Send）无效就暂停。

```text
发送方 RTS ───► 接收方 CTS
发送方 CTS ◄─── 接收方 RTS
```

这块板默认 **无流控**（`flow=n`），因为目标设备不一定有
RTS/CTS 两根线。没有流控时，只能靠：

- 足够大的环形缓冲吸收突发。
- 应用层背压（发慢了就等）。
- 丢数据并计数（最坏情况）。

运行时可以通过命令开启：

```text
@u=115200,8,n,1,rtscts
```

但前提是硬件真的接了这两根线。

> 流控不是“更高级所以更好”。线没接却开流控，反而会卡死。

## 5.7 实验：回环测试

### 目的

在不接目标板的情况下，验证“你的串口工具 + 驱动 + 线”是好的。

### 做法

把 USB-TTL 模块的 **TX 和 RX 短接**（只接这两根，不要接 VCC）：

```text
USB-TTL
  TX ──┐
       ├── 短接
  RX ──┘
```

然后：

```sh
picocom -b 115200 /dev/ttyUSB0
```

随便敲字符，应该原样回显。退出 `Ctrl-A` `Ctrl-X`。

### 如果回显不正常

| 现象 | 原因 |
|---|---|
| 什么都没回 | TX/RX 没短接、模块坏、设备节点选错 |
| 乱码 | 波特率不对、模块时钟不准 |
| 只回一部分 | 流控、缓冲区、USB 掉包 |
| 权限错误 | 不在 `dialout` 组 |

### 不装 picocom 也能测

```sh
# 配置串口
stty -F /dev/ttyUSB0 115200 cs8 -cstopb -parenb raw -echo

# 后台读
cat /dev/ttyUSB0 &

# 写
printf 'hello\n' > /dev/ttyUSB0
```

应该看到 `hello` 被回显。结束记得 `kill` 掉 `cat`。

> `stty` 是理解串口参数的好工具：`cs8` 是 8 数据位，
> `-cstopb` 是 1 停止位，`-parenb` 是无校验，`raw` 是不要
> 行缓冲/回显处理。

## 5.8 一个最小的 C 串口程序

```c
/* serial_echo.c —— 打开串口，把收到的字节打印出来 */
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <termios.h>

int main(int argc, char **argv)
{
    const char *path = argc > 1 ? argv[1] : "/dev/ttyUSB0";
    struct termios tio;
    char buf[128];
    int fd;

    fd = open(path, O_RDWR | O_NOCTTY);
    if (fd < 0) {
        perror("open");
        return 1;
    }

    if (tcgetattr(fd, &tio) < 0) {
        perror("tcgetattr");
        close(fd);
        return 1;
    }

    cfmakeraw(&tio);                 /* 原始模式：不做行缓冲/回显 */
    cfsetispeed(&tio, B115200);
    cfsetospeed(&tio, B115200);
    tio.c_cflag |= (CLOCAL | CREAD);
    tio.c_cflag &= ~CSTOPB;          /* 1 停止位 */
    tio.c_cflag &= ~PARENB;          /* 无校验 */
    tio.c_cflag &= ~CSIZE;
    tio.c_cflag |= CS8;              /* 8 数据位 */

    if (tcsetattr(fd, TCSANOW, &tio) < 0) {
        perror("tcsetattr");
        close(fd);
        return 1;
    }

    printf("reading %s at 115200 8N1, Ctrl-C to stop\n", path);
    for (;;) {
        ssize_t n = read(fd, buf, sizeof(buf));
        if (n < 0) {
            if (errno == EINTR) {
                continue;
            }
            perror("read");
            break;
        }
        if (n > 0) {
            fwrite(buf, 1, (size_t)n, stdout);
            fflush(stdout);
        }
    }

    close(fd);
    return 0;
}
```

```sh
gcc -Wall serial_echo.c -o serial_echo
./serial_echo /dev/ttyUSB0
```

> 这个程序只读不写。想双向，就在 `stdin` 可读时 `write(fd, ...)`，
> 或者用 `select` 同时等两个 fd。第 19 章会写完整版。

## 5.9 常见错误清单

| 现象 | 第一嫌疑 | 怎么查 |
|---|---|---|
| 全是乱码 | 波特率/帧格式 | 两端都设 115200 8N1 |
| 完全没输出 | 接线、共地、选错口 | 回环测试、`dmesg` |
| 偶尔丢字节 | 溢出、无流控、缓冲太小 | `@i?` 的 drop、加缓冲 |
| 只能收不能发 | TX 没接/接错 | 交换 TX/RX 再试 |
| 一接就发热 | 两个 TX 对接、5 V 进 3.3 V | 立刻断电，查电平 |
| 拔插后设备名变了 | USB 枚举顺序 | `ls -l /dev/serial/by-id/` |
| 权限拒绝 | 不在 `dialout` | `groups`、`usermod` |
| 串口被占用 | 另一个程序没退 | `fuser /dev/ttyUSB0` |
