# 附录 G：实验台、接线与安全检查

> 这一篇把书里散落的“怎么接、用什么东西、通电前查什么”集中起来。
> **接线错误是嵌入式最常见、也最容易烧板的事故。**

## G.1 最小物料清单

| 物品 | 规格 | 必需 | 用途 |
|---|---|---|---|
| V851S 板子 | YuzukiPI-Lizard 或同类 | ✅ | 主设备 |
| USB-C 数据线 | 能传数据，不只是充电 | ✅ | 供电 + A7 控制台 |
| USB-TTL 模块 | CH340/CP2102，**3.3 V 电平** | ✅ | E907 UART3 / 目标串口 |
| 杜邦线 | 母-母或母-针，按板子接口 | ✅ | 接线 |
| 网线 / Wi-Fi | 2.4 GHz | ✅ | 联网 |
| 目标板 | 任意带 UART 的开发板 | 推荐 | 被调试的一端 |
| 万用表 | 通断/电压 | 推荐 | 查线、量电平 |
| 逻辑分析仪 | 24 MHz 以上 | 选配 | 看 UART 波形 |
| USB 电流表 | — | 选配 | 判断供电是否不足 |
| 备用板 | 同型号 | 选配 | 刷机/救砖演练 |

### 不要用

```text
❌ 5 V 电平的 USB-TTL 直接接 3.3 V 引脚
❌ RS-232 电平（±12 V）直接接 TTL 串口
❌ 只有充电功能的 USB 线（枚举不到串口）
❌ 快没电的充电宝 / 劣质电源
```

## G.2 三组串口，别接混

这块板上有三条容易混淆的“串口”：

```text
1. A7 控制台（Linux console）
   板载 USB-C → CH343P → /dev/ttyACM0
   115200 8N1

2. E907 的 UART3（目标串口）
   PE12(TX) / PE13(RX) → 外接 CH340 → /dev/ttyUSB0
   115200 8N1

3. 目标板自己的 UART
   由你的目标板决定，通常也是 115200 8N1
```

### 一张图

```text
主机
 ├─ USB-C ──────────────► 板子（A7 console, /dev/ttyACM0）
 │
 └─ USB ─► CH340 ─┬─ TX ─► PE13 (E907 UART3 RX)
                  ├─ RX ◄─ PE12 (E907 UART3 TX)
                  └─ GND ── GND
```

> **TX 接 RX，RX 接 TX，GND 接 GND。** 这三句话能解决一半的“没输出”。

### 为什么不能接 VCC

```text
两边都有供电 → 电源打架 → 轻则枚举失败，重则烧稳压器
```

USB-TTL 只接 **TX / RX / GND** 三根线。除非你明确知道自己在做什么，
否则不要接 VCC。

## G.3 通电前检查清单

每次改线后，按顺序检查：

```text
1. 断电（拔掉 USB-C 和 USB-TTL）
2. 确认 TX/RX 是交叉的
3. 确认 GND 相连
4. 确认没有接 VCC（除非设计需要）
5. 确认电平是 3.3 V
6. 用万用表通断档确认没有短路（尤其是 3.3V 与 GND）
7. 先插 USB-TTL，再给板子上电
8. 打开串口终端，确认波特率 115200
```

### 上电后

```text
- 有没有异味/发热异常 → 立刻断电
- 串口有没有启动日志 → 没有就看接线和端口
- 电流是否异常 → 用 USB 电流表
```

> 发热、异味、电流飙高，**先断电再分析**。不要“再看一眼”。

## G.4 实验 0：USB-TTL 回环（不接板子）

目的：确认“主机 + 串口模块 + 终端软件”这条链是好的。

```sh
# 1. 找设备
ls -l /dev/ttyUSB*
dmesg | grep -i ch34

# 2. 短接模块自己的 TX 和 RX（只短接这两个，不接 VCC）
# 3. 打开终端
picocom -b 115200 /dev/ttyUSB0

# 4. 输入字符，应该原样回显
# 退出：Ctrl-A 然后 Ctrl-X
```

也可以用命令行：

```sh
stty -F /dev/ttyUSB0 115200 cs8 -cstopb -parenb raw -echo
cat /dev/ttyUSB0 &
printf 'loopback-test\n' > /dev/ttyUSB0
```

看到 `loopback-test` 就说明模块和驱动正常。

### 失败时

| 现象 | 检查 |
|---|---|
| 没有 `/dev/ttyUSB0` | 线、驱动、`dmesg` |
| 打不开 | 被别的程序占用、权限 |
| 乱码 | 波特率、时钟 |
| 无回显 | TX/RX 没短接对 |

## G.5 实验 1：A7 控制台

```sh
picocom -b 115200 /dev/ttyACM0
```

应该看到 U-Boot / 内核日志，最后是登录提示。

```text
Hit any key to stop autoboot: 3
...
v851s login:
```

> 这是“最后一道门”。**只要它还在，板子就没死。**

## G.6 实验 2：E907 UART3

接线：

```text
CH340 TX  → PE13
CH340 RX  ← PE12
CH340 GND ↔ GND
```

```sh
picocom -b 115200 /dev/ttyUSB0
```

如果 E907 固件已经在跑桥接，网页上发的字符会从这里出来；
从这里输入的字符也会出现在网页上。

### 验证方向

```text
网页 → 目标串口：在网页输入，picocom 里看到
目标串口 → 网页：在 picocom 输入，网页里看到
```

> 两个方向都要测。**只测一个方向，可能只是回显。**

## G.7 实验 3：接一块目标板

```text
E907 UART3 TX (PE12) → 目标板 RX
E907 UART3 RX (PE13) ← 目标板 TX
GND ↔ GND
```

### 电平确认

```text
V851S：3.3 V TTL
目标板：查原理图，确认是 3.3 V 还是 5 V
```

如果目标板是 5 V TTL：

```text
需要电平转换（双向电平转换模块）
或确认目标板 RX 能容忍 3.3 V（很多可以，但不能假设）
```

### 共地

```text
两块板不共地 → 电平没有共同参考 → 乱码/无输出
```

> 共地不是“可选优化”，是**通信的前提**。

## G.8 引脚怎么找

### 方法一：看丝印

```text
板子背面/排针旁通常标：PE12、PE13、GND、3V3、5V
```

### 方法二：看原理图

```text
找 SoC 的 PE12/PE13，确认接到哪个排针/测试点
确认有没有电平转换/隔离
```

### 方法三：通断测试

```text
万用表通断档：一端接排针，一端接 SoC 引脚/测试点
```

### 方法四：软件确认

```sh
# 读 PIO 配置（需要 root，地址见附录 C）
devmem 0x020000C4 32
```

> 不要凭“排针顺序看起来像”去接。**接错电源引脚可能直接烧板。**

## G.9 常见接线错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| TX 接 TX | 双方都在说，没人听 | TX→RX 交叉 |
| 不接 GND | 乱码/无输出 | 必须共地 |
| 接 5 V 到 3.3 V 引脚 | 可能烧芯片 | 确认电平/转换 |
| 接 VCC | 电源打架 | 只接 TX/RX/GND |
| RS-232 直连 TTL | 烧接口 | 用电平转换 |
| 线太长/无屏蔽 | 高速下误码 | 缩短、双绞、降速 |
| 热插拔 TX/RX | 瞬时电流 | 断电改线 |
| 用充电线 | 枚举不到串口 | 换数据线 |

## G.10 安全规则

```text
1. 改线先断电
2. 不确定就先用万用表
3. 第一次上电用手放在电源附近，异常立刻拔
4. 不要在主板上做“飞线”实验（除非你接受风险）
5. 备用板用于刷机/救砖演练
6. 锂电池/大电流电源要有保护
7. 不要让板子悬空短路（垫绝缘）
```

### 出问题时的顺序

```text
断电 → 检查接线 → 量电压/通断 → 换线/换模块 → 再上电
```

> 不要“再插一次试试”。**短路不会因为多插一次而变好。**
