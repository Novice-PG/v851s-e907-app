# 第 0 章 这本书怎么用

> 本章目标：
> 1. 知道自己现在在哪、学完会到哪。
> 2. 把学习环境准备好。
> 3. 接受三条学习规则，避免中途放弃。

---

## 0.1 先做一次自我评估

不用打分，只需要诚实回答：

1. 给你一段 C 代码，里面有 `struct`、指针、`malloc`，你能说出每个变量大概在干什么吗？
2. 你能用 `ssh` 登录一台 Linux 机器，用 `cat`、`grep`、`ps`、`chmod` 吗？
3. 你知道“编译”和“运行”是两步，而不是一个按钮吗？
4. 你见过 `Permission denied`、`No such file or directory` 并自己解决过吗？
5. 你能接受“先照着做，做完再理解”吗？

如果 1～4 里有两项以上是“不能”，先补第 3、4 章；
如果第 5 项是“不能”，这本书会很痛苦，因为嵌入式必须动手。

> 这本书不要求你聪明，只要求你不跳过实验。

## 0.2 学完是什么样

不是“知道很多名词”，而是能独立完成下面这些事：

### 能看懂

- 一块板子的启动日志，知道卡在 boot0、U-Boot、内核还是 init。
- 一个异构系统的内存地图，知道哪些地址不能碰。
- 一个 daemon 的线程模型，知道哪个线程会阻塞谁。
- 一个 BLE GATT 服务，知道手机写一个特征值后数据去了哪。
- 一个网页终端，知道 WebSocket 帧怎么变成串口字节。

### 能动手

- 在 Zephyr 上新建线程，用信号量和环形缓冲。
- 给一块新板子写 board 文件、DTS、pinmux。
- 写一个 Linux 串口 daemon，处理断线、背压、多客户端。
- 写一个最小 HTTP/WebSocket 服务器。
- 设计一个 BLE 服务，算 MTU 和分片。
- 写 Web、TUI、CLI、Android 四种客户端中的至少两种。
- 构建 rootfs、打包、刷机、救砖。

### 能判断

- 一个问题出在硬件、驱动、RTOS、Linux、网络还是前端。
- 一个改动会不会破坏启动链、掉电安全、数据持久化。
- 一个性能问题该测什么，而不是盲目调参数。
- 一个安全问题是不是“设计取舍”，而不是“加个密码就行”。

## 0.3 学习环境

### 主机

推荐 Ubuntu 22.04/24.04 或 Debian 12。Windows 用户用 WSL2 或虚拟机。

最低配置：

- 4 核 CPU、8 GB 内存、40 GB 空闲磁盘。
- 能访问互联网（拉代码、装包）。
- 至少一个 USB-A 口（接 USB-TTL）。

### 必备软件

```sh
sudo apt update
sudo apt install -y \
  build-essential git cmake ninja-build python3 python3-pip \
  gcc-arm-linux-gnueabihf gcc-riscv64-unknown-elf \
  device-tree-compiler picocom minicom \
  curl openssl net-tools iproute2
```

> 包名因发行版而异。装不上不是你的错，先查发行版文档，
> 不要直接复制一堆“万能命令”。

### 串口权限

Linux 下普通用户默认不能读写 `/dev/ttyACM0`、`/dev/ttyUSB0`：

```sh
sudo usermod -aG dialout "$USER"
# 退出登录再重新登录，或重启
```

验证：

```sh
ls -l /dev/ttyACM0 /dev/ttyUSB0
groups
```

你应该看到 `dialout` 组里有你的用户名。

### 串口工具

`picocom` 最简单：

```sh
picocom -b 115200 /dev/ttyACM0
# 退出：Ctrl-A 然后 Ctrl-X
```

`minicom` 功能更多，但第一次配置容易迷路。本书默认用 `picocom`。

### 板子访问

两种方式：

1. **串口控制台**：`/dev/ttyACM0`，115200，8N1。
2. **SSH**：`ssh root@<board-ip>`，需要板子联网。

> 串口是“最后一道门”。网络挂了、SSH 连不上、系统起不来，
> 都靠它。先学会串口，再依赖 SSH。

## 0.4 三条学习规则

### 规则一：先跑，再懂

面对一个新系统，最有效的顺序是：

```text
跑起来 → 看日志 → 改一个参数 → 看变化 → 再读代码
```

不是：

```text
读完整本内核书 → 再动手
```

> 你不需要先懂发动机才能学开车。但你必须知道刹车在哪。

### 规则二：每章只问三个问题

读任何代码，先回答：

1. 它在**哪个 CPU / 哪个进程**上跑？
2. 它读写的对象是**内存、寄存器、文件、socket 还是网络**？
3. 它失败时，**谁会先发现**？

这三个问题能帮你穿过 90% 的术语。

### 规则三：不做完验收，不进入下一章

每章末尾有“验收”。它不是考试，而是“你真的跑过吗”的证明。

> 看懂别人的代码，和能改自己的代码，是两种能力。
> 验收只检查后者。

## 0.5 一次完整的学习循环

以“让 E907 的串口回显一个字符”为例：

1. **跑**：按书里的命令，看到字符回来。
2. **看**：`trace0` 有没有日志？`@i?` 的 buffer 变了吗？
3. **改**：把波特率从 115200 改成 9600，观察乱码/恢复。
4. **拆**：读 `linkr_bridge.c`，找到 `uart_configure()`。
5. **造**：自己加一个 `LINKRPING` 控制命令，返回 `PONG`。

这就是“从使用者到作者”的循环。每一章都应该走一遍。

## 0.6 遇到问题怎么办

### 第一步：收集事实

不要先说“坏了”，先回答：

- 你执行了什么命令？
- 期望是什么？
- 实际输出是什么？
- 最近改过什么？
- 有没有备份？

### 第二步：分层定位

```text
电源 → 串口 → boot0 → U-Boot → 内核 → init → 服务 → 网络 → 浏览器
```

从最底层往上查，不要一上来就重装系统。

### 第三步：最小化

- 只改一个变量。
- 只跑一条命令。
- 只连一个客户端。
- 只保留最小代码。

### 第四步：记录

把“现象、原因、解决”写进笔记。下一次你会感谢自己。

> 这本书的“常见错误”章节不是让你背，而是让你知道：
> **别人也踩过，这不是你笨。**

## 0.8 本章验收

完成下面 5 项，才算准备好：

1. 主机上 `gcc --version`、`cmake --version`、`ninja --version` 都能输出。
